## 1. 一句话定位

一个「一切皆实例」的通用 agent harness：
把提示词、人格、工具、技能、记忆、工作区全部注册成**可寻址的实例**，
用一套统一消息流让它们协作；**GUI 只是这条消息流的投影**。

工具与服务不预先绑定到某个智能体，而是**运行时按需拉起、按绑定注入** ——
「万物服务」+ 一个中控（§6）。智能体只知道"我有什么、怎么问"，
不知道"这个工具内部是什么技术栈"。

「无视技术栈」是结果，不是目标 —— 因为工具是独立服务，
它内部是 Rust / Go / Python / 一个 Docker 容器都不重要，
框架只认它暴露的消息接口。

「通用」也不是靠一套万能代码，而是靠**换绑定不换代码**（§2.3）。

### 1.1 三句话定位（2026-09-18）

对齐了 deepseek-harness 之后（§20），这个项目的定位可以压成三句，
**三块互不重叠**：

1. **内核是分布式的那一种** —— 不是一个进程里的插件树，而是**多个进程组成、
   由中控仲裁的一张图**。dsh 是插件容器，我们是分布式系统（§20.4）。
2. **GUI 那条轴是独有的** —— 窗口托管、控制通道阶梯、观察分级、虚拟点击、
   元素动作阶梯。**deepseek-harness 完全没有这条线**（它没有 window / computer /
   UIA 任何一类包），而这条轴占了本文档最厚的两块（§13 + §14）。
3. **工具、沙箱、压缩那几个形状是收敛的** —— 和 dsh 独立收敛到同一组结论
   （spill / pty / sandbox / inject / invariant）。**可以直接照抄形状**，
   把力气留给前两条。

**为什么不说"复刻"**：本文档第 3 轮就提出了"万物服务 / 一切皆实例"，
那时还没读过 dsh。**收敛说明形状由问题决定，不由口味决定** ——
这比"我想出了一个别人没想到的东西"更可靠。

## 0. 原始表述（先原样记下，别丢）

> 我在想一个新的 harness 框架，这是在经历了无数的离散开发之后想到的：
> 将一切，包括提示词、人格、工具、技能等等，都注册成为**实例**，
> 这样就能在一个框架内造出通用的东西，并且**无视技术栈**。
>
> 比如那个网安相关的东西（pentagi），就可以把知识库和工具等等注册成为一个
> 后台运行的小服务，通过某种方式托付给一个智能体，智能体在提示词中了解到
> 自己有这些工具，然后进行调用 —— 有点类似于 MCP？
> 但是我希望它更像是一个**响应式的 tool**，然后规定一套**消息流**，
> 这样画 GUI 的时候实际上只是接收智能体和各种工具的 IO。
>
> 大概是这样：
> - **智能体**：带有基本信息，可以选择模型和人设之类的，还需要动态拼接提示词
> - **工具**：有自己的唯一 ID 和参数表，还要通过识别码之类的手段对智能体的请求鉴权，然后返回调用的结果
> - **记忆系统**
> - **工作区**


### 0.1 补充表述（2026-09-13 第二轮）

> 我是想基于过往的成果和开发经验造出**新的** harness。
> 我细品了一下，好像其实就是 MCP？但我的设想是「**万物服务**」：
> 被允许使用的工具和知识，在**实例阶段动态注入**目标智能体。
>
> 出于避免爆掉上下文的考量，不能全量注入。应该是：比如把一个网安相关的东西
> 交给一个智能体，这个智能体在**提示词阶段**就接到说明，被告知它有这个工具，
> 以及**该如何去获取这个工具的相关知识** —— 有点像用命令行时面对一个不熟的工具，
> 打出工具名加 `--help`。
>
> 然后程序开始运行时有一个**中控**，负责动态拉起这些工具的服务进程，
> 并在 GUI 上显示出来方便管理。

### 修订说明：第一版无 GUI，全程 stdio

**第一版不是一个应用，是一个能用管道对话的内核。**

无 GUI 不是"简化版"，而是**完整的内核** —— 因为 GUI 只是消息流的一个订阅者（§12.6）。
少了它，内核仍然自洽。而且这带来一条可测判据：

> **能用 stdio 跑通 ⟺ 内核真的独立于 UI。**
> （和 §9 那条"能从日志重建 UI"是同一个形状的检验。）

**顺带纠正一个我之前的说法**：我说过"没有最小中控，工具实例跑不起来" ——
但**"中控"不是 GUI 应用，它是内核的功能模块**（生命周期、注册表、路由、仲裁、审计）。
**GUI 是它的订阅者，不是它本身。** 所以无 GUI 的版本里，中控就是内核的那几个模块。

### 阶段 1：stdio 传输 + 最小内核

**传输**：每行一个 JSON 消息（NDJSON）。
**和 MCP 的 stdio 传输同形** —— 以后接 MCP 不用另写传输层。

**内核**：实例注册表 + 消息流 + 中控那几个模块（拉起服务、路由、仲裁）。

跑起来的标志：**手写几行 NDJSON 喂进去，能拿到结构正确的回复。**

#### ✅ 2026-09-19：跑通了

```text
crates/harness-core    信封 / NDJSON 编解码 / 会话日志 / 三条不变量
crates/harness-ctrl    中控：注册表、路由、裁决、落盘屏障
crates/harness-echo    mock 工具服务（上线自报 manifest）
scripts/smoke-stdio.ps1   验收脚本，10 条判据
```

跑法：`pwsh -File scripts/smoke-stdio.ps1`（会自己 build，再拿手写的 NDJSON
喂进去，最后把 stdout、stderr、会话日志三份都打出来）。

它证明的是一条完整链：

```text
console ──request──▶ ctrl ──▶ echo:1 ──chunk+result──▶ ctrl ──▶ console
                        │
                        └── 每条都先落进 log.jsonl，再投递
```

**它第一次跑就抓到一个真 bug**（决策册「内核与协议」已记）：中控把
"发给自己的 presence"也当成了 op，于是对着服务回了一句没人问过的
"我不认识 op=(空)"。修法：**只有 `request` 才是让中控做事**，
其余种类发给中控是汇报。这个 bug 已经钉成第 8 条判据。

### 阶段 2：第一个工具实例

**编辑器先上，终端排第二**（2026-09-18 定）。

走通这条链：**manifest 自报 → 实例创建 → 工具调用 → 事件回传 → 图上出现节点**。

**这意味着"写互斥"（§5.15）最先被验证** —— 它恰好是这套设计里最新、
也最没有先例可抄的那个机制（"实例是锁点"）。
终端排第二，它检验的是抽象能不能撑住第二个工具实例。

#### ✅ 2026-09-19：编辑器与终端都跑通了

```text
crates/harness-service/src/fence.rs        路径围栏（两道闸门，两个服务共用）
crates/harness-service/src/domain_lock.rs  域锁（一个域一个进程）
crates/harness-editor/                     编辑器：写锁 + 回滚
crates/harness-term/                       终端：命令模式 + 游标读 + 杀进程树
scripts/smoke-editor.ps1                   验收：18 条判据
scripts/smoke-term.ps1                     验收：19 条判据
```

**编辑器**那份建一个临时项目、拉起**两个**编辑器进程托管它，然后从 console 喂 NDJSON：
开文件、重复开（幂等）、往围栏外绕、文件不存在、新建、改、读、回滚、两种 `old`
不命中、status、关掉、关掉之后再开。

**终端**那份专门验"同形不同质"：`run` 是**异步**的（先流式 `chunk`、最后 `result`），
**命令失败 ≠ 调用失败**（exit 3 但 `effect: confirmed`），`cd` 的围栏
（路径内可以、出去就拒），实例内部串行（跑着时再来一条是 `busy`），
游标读，以及"关掉正在跑命令的终端时那条命令不被静默丢弃"。

> ⚠️ **异步工具的验收脚本必须一问一答地喂。**
> 把一批请求一次性灌进去，后面的会在第一条命令跑完之前到齐，于是全部撞 `busy` ——
> 那不是被测对象的问题，是测法的问题。真实的智能体也正是"发一条、等结果、再发下一条"。

**这两份一共抓到五件事，一件都不是预想的**（决策册里逐条记了）：

1. **新建的空文件没法写入** —— `edit` 要求 `old` 恰好命中一次，空文件永远命中不了。
2. **两个编辑器进程 = 两张锁表 = 写互斥失效** —— 责任在应用，不在中控（见下）。
3. **`close` 把未决的那次 `run` 吞了** —— 终端被移出表之后 `on_done` 找不到它就直接返回，
   那条调用永远没有结果。和之前 ctrl 那个 bug 是同一类：**未决调用被静默丢弃**。
4. **杀 `cmd.exe` 不等于杀进程树** —— 超时掐掉的只是 shell，它启动的 `ping.exe`
   还活着并**继续攥着 stdout 管道**，读线程永远等不到 EOF。修法：Windows **Job Object**
   + `KILL_ON_JOB_CLOSE`，一次带走整棵树，句柄一关自动清干净。
5. **一行非 UTF-8 字节让整条控制通道静默死亡** —— 触发者是 PowerShell 的
   `StandardInputEncoding` 默认走**系统 ANSI 代码页**（中文 Windows 上是 GBK），
   于是那行中文被编成 GBK 字节，ctrl 一读到非法 UTF-8 就放弃读取。
   修法：**坏行跳过 + 报错即手册**（错误里直接点名最可能的成因）——
   中文环境里谁都会踩这个坑。

第 2 条的修法我一开始想错了：我提议"把锁表上移到中控"，**那等于让内核去懂每个工具
的内部语义**。正确形状是**同一个域只能有一个服务进程，冲突由应用在注册/启动时自己挡住** ——
编辑器启动时对每个托管根取一把**域锁**（Windows 命名互斥体，进程死了由内核自动释放），
撞上就进 **`degraded`**：照常在线、不接活、只回 `ping`/`status` 说明原因。

> **责任在哪一层，是一个容易记错的地方。**
> 中控的职责边界是**注册与路由**，不是域内资源仲裁 ——
> 让内核去懂每个工具的内部语义，正是这套设计一开始要避免的（§5.10、§5.15）。

> 两件事顺带定了：**摘要请求算一次要记的模型调用**（记事实：哪条路、多少 token、
> 有没有退回 —— 摘要正文本来就进 `summary`，所以**能重建**且日志不被撑大）；
> **失败不能把压缩整个取消**（那会把上下文顶爆），但**也绝不装作那是模型的摘要** ——

```text
crates/harness-memory/src/window.rs     窗口与基线（prefill_input_tokens）
crates/harness-memory/src/policy.rs     绑定级策略（ratio / aggressiveness / keep / 风格）
crates/harness-memory/src/history.rs    轮次切分 + **安全切点** + 不变量断言
crates/harness-memory/src/compact.rs    压缩动作 + 一等事件的记录 + pre/post 钩子
crates/harness-memory/src/summarize.rs  可插拔摘要器（mock 先行）
scripts/smoke-memory.ps1                验收：四个场景、14 条判据
```

跑法：`pwsh -File scripts/smoke-memory.ps1`；想自己看，就
`cargo run -p harness-memory -- demo --window 1200 --turns 16`。
输出长这样（一轮一行，触发那一轮会打出压缩记录）：

```text
  轮   估算token      窗口  事件
  10       878       1  -
  11       965       2  触发（80% of 窗口）；[压缩] context_limit / pre_turn / mock
                         → 窗口 1→2（965 → 427 token，压掉 7 轮，摘要 270 字节）
  12       514       2  -
```

**四条硬要求，每条都有判据盯着**：不到触发线绝不压；压完要落到目标附近
（"反正都是炸缓存，不如把新东西放少点"）；**切点落在"没有悬着调用的位置"**，
所以一次工具调用和它的结果**不可能被切开**（配一条运行时断言）；
压缩是一等事件（新窗口 + 留旧窗口 id + pre/post 钩子 + 完整记录）。

> **📌 2026-09-20 第三条放宽了**（待定 #105 结账）：原来是"切点在**轮次边界**"，
> 而一个回合内部没有任何边界 —— 于是一个智能体在**同一个回合里**连做几十次工具调用时，
> 历史会一路涨到撞窗口而**中间没地方可切**。现在切点细化到**调用对粒度**：
> 只要那个位置上"没有调了还没回的调用"，就能切。
>
> 代价说清楚：`keep_recent_turns` 从**硬下限**变成**软下限** ——
> 保底那几轮自己就装不下目标时，会**往最早那一轮内部切**，只保底留最后一个完整段落。
> 这条不变量也跟着升级：从"数个数"变成**按 `call_id` 配对**
> （"个数对得上"不等于"配得上"）—— 它当场抓到一个真 bug：**超时那条结果没带 `call_id`**，
> 而真 provider 那边「`tool_calls` 必须有对应回信」会因此**拒绝整条请求**。

**这一轮又抓到三件事：**

1. **"压到目标"是个做不到的保证。** "至少保留 `keep_recent_turns` 轮"是硬约束 ——
   最近几轮本身就比目标大的话，压不过去。所以判据只能是"落到触发线**以下**"。
   我原来的断言照着"目标"写，第一次跑就挂了。
2. **预算是整数，得四舍五入。** `0.8 × (1 − 0.9) × 1200` 在二进制浮点里是
   `95.99999999999999`，截断就得到 95 —— 同一个配置算出两个数，判据立刻变玄学。
3. **只能有一条摘要。** `MidTurn` 那种放法会让上一次的摘要落进保留区，
   而它的内容**已经折进新摘要**了；留着就是两份互相矛盾的历史。
   新摘要必须看得见旧摘要（否则信息一次比一次薄），旧的那条必须删掉。

#### ✅ 2026-09-20：**沉淀式记忆服务**（`harness-mem`）—— 原始四块里最后一块

阶段 3 做的那个是**线性**记忆（智能体进程里、每一轮都在算、跟着窗口活）。
§5.4.4 定过：沉淀式不是它的替代品，是**另一条路线**，两者在"会话结束 / 切项目"
那个点上接起来。这一块做出来了，形状是**一个服务实例**：

```text
crates/harness-mem/src/store.rs   碎片库：一个锚点一本账，只追加 + 折叠
crates/harness-mem/src/main.rs    服务：deposit / recall / list / pin / forget / help
scripts/smoke-mem.ps1             验收：19 条判据（含跨会话与域锁）
```

**这一层最容易骗人的地方，正好也是判据最多的地方**（19 条里 12 条在问这个）：

| 问题 | 它现在怎么答 |
|---|---|
| 同一条话写两遍？ | **认出来**（内容指纹幂等）：回你原来那条的 id，`stored: false` —— 不是假装又写成功了 |
| "没变"是不是真的没变？ | 锚点指纹覆盖**内容 + 钉没钉 + 忘没忘**，**不是条数**；带 `if_none_match` 就只回 `unchanged: true`，一个字的正文都不给 |
| 过期的碎片被删了吗？ | **没有**。默认不给看，但 `expired_skipped` 把"少了几条"数出来（§16.6：降级必须显式）|
| `forget` 是把行删了？ | **立墓碑**：默认不再给你，但"当初为什么不算数了"留在账上 |
| 不认识的分类怎么办？ | 拒，并把那五个（`fact` / `decision` / `experience` / `opinion` / `pointer`）列出来 —— 它是**可信度的唯一依据**（§16.10）|
| 文本太长？ | 拒，并指出去哪儿放长文（碎片只留结论 + 一个 `pointer`）—— 碎片一旦能装整篇文章，召回就等于把仓库倒进上下文 |
| 一条记忆挂在哪儿？ | **调用方给锚点**，服务不猜。谁托管谁才知道"这次会话对应哪个项目"（§16.5）|

顺带钉住两件架构上的事：**能力校验确实在服务侧**（`mem.write` / `mem.read` /
`mem.curate` —— 中控只签发，不知道 recall 要什么），以及**一处碎片库只许一个进程写**
（域锁 ⇒ 撞上就进 `degraded`：在线、不接活、只回诊断）。第二条是从编辑器那件事学来的。

> **这一层没做的，也写在 `not_implemented` 里**：召回是**字面匹配**，不是语义匹配；
> "没召回出来"**不等于**"这事没发生过"。锚点也**不建实例**（图上看不到它落在哪本账上）。

#### ✅ 2026-09-20：**技能（知识）服务**（`harness-skill`）—— "知识库托付给智能体"那个形状

§3 的清单里"技能"的定义是"**一份怎么做某类事的知识/流程**，版本化，不需要常驻"。
它现在是一个服务实例，要证的核心只有一句：**渐进披露真的能省上下文，不是口号。**

```text
crates/harness-skill/src/loader.rs   扫目录 + 两种形状 + 按标题切章 + 按行分页
crates/harness-skill/src/main.rs     服务：list / open / search / status / help
scripts/smoke-skill.ps1              验收：14 条判据
```

读法是三段，**每一段给的东西严格不一样**（§5.3）：

| 这一声 | 给你什么 | 为什么不给更多 |
|---|---|---|
| `list` | 名字 + 一句话 + **章节目录** | 正文一个字都不给 —— 判据就是拿全文去搜，搜不到才算过 |
| `open {skill}` | 那一份的章节目录（带每章行数） | 让你**挑**，不是让你**读** |
| `open {skill, chapter, from_line?}` | **那一章**的正文，一页 120 行，给不完回 `next_line` | 一章可能是几万字 —— 你要的是做法，不是背下来 |
| `search {query}` | 命中处：技能 / 章 / **行号** / 那一行 | 只给命中那一行，上下文自己按行号去要 |

**按行分页而不是按字节**：字节会**劈开一个汉字**（终端那边溢出就是这么处理的，这里沿用）。

两种技能目录都收，**不为格式重写一遍别人的东西**：一个有 `skill.json` 的（能写清
`version` / `when_to_use` / 章的顺序），或者**只有一个 `SKILL.md`** 的
（按 `## ` 标题自动切章）—— 后者才是现成的技能目录长的那样，抄过来就能用。

三条"它会不会骗人"的判据：

* **坏掉的技能目录不许悄悄跳过**：加载时收进 `skipped`，`status` 里连原因一起报出来 ——
  "少了三份技能"和"那三份坏了"是两件完全不同的事；
* **名片里不许漏正文**：这条是**测试逼出来的** —— 一开始"一句话介绍"是从全文里抓第一个
  非标题段落，于是**第一章的正文漏进了名片**。现在只认第一个 `## ` 之前那段，
  前言里没写就照实说"没写"，绝不从正文里抓一句充数；
* **刚写的技能不重启服务就看得见**：技能是文件，写它的人不会来通知你 —— 默认每次调用重扫。

> **三个服务，三种 scope。** 文件域是**围栏**（哪条路径），记忆域是**锚点**（哪本账），
> 技能域是**这个根目录里放了什么**。令牌一样是纯标签（`fs.write` / `mem.write` / `skill.read`），
> 变的只是"范围"那个词在每个域里指什么。技能域**只做到这里**：
> "只给某个智能体看其中几份技能"**没有机制**，写在 `not_implemented` 里了。

#### ✅ 2026-09-20：**第二个传输 + 常驻服务**（`lifecycle: resident`）—— "分布式"那句话终于成立

在这之前，每个服务都是中控的子进程，通道是 stdin/stdout —— **父子私有**。
中控一收摊通道就没了，服务跟着走。所以"多进程组成的图"其实是**每会话一张小星形图**：
跨会话共享一个进程**根本写不出来**。

这一块补上之后，形状变了：

```text
   会话一 ──拉起──▶ mem:1（写会合文件、听回环端口）
      │                    ▲
      └── 收摊 ✕ 不收它     │ **接上（不是再起一个）**
                       会话二 ── 同一批碎片、同一个进程
```

| 新东西 | 是什么 | 为什么必须这样 |
|---|---|---|
| **`harness-ipc`** | 第二个传输：回环 TCP + 口令 + **会合文件** | stdio 是父子私有的，"别的会话接上来"在它上面写不出来。命名管道要一大片 FFI，而这一层要证的是**协议与传输解耦**，不是"用上了管道" |
| **会合文件** | 服务写 `{addr, token, pid, started_ms, protocol}`；后来的会话靠它找过来 | ⚠️ **它不是真相**：进程崩了不会来删它。所以接上之前**必须真的连一次** —— 和"磁盘指纹""锚点要重新解析"同一条纪律 |
| **`stop` 入口** | 服务在 manifest 里声明"收我调哪个工具" | 常驻服务**可能不是这个会话拉起来的** ⇒ 中控手里**没有那个子进程句柄**，"杀进程"这条路不存在 |
| **`NoInheritStdio`** | 拉起前摘掉中控自己那三根句柄的"可继承"位，拉完还原 | 子进程会继承你的输出管道。而它活得比你久 ⇒ 管道**永远不到 EOF** ⇒ 别人读你的输出会**静悄悄卡到超时**（这个 bug 是 smoke 第一次跑就撞上的） |

收一个常驻服务分两段，**因为"我能不能让它死"取决于它是不是我起的**：

```text
   先礼：发一条 request 调它声明的 `stop` 入口 —— **只发不等**
         （中控单线程，在这儿等回信就是死锁，自己等自己）
   后兵：我起的 ⇒ 有句柄，直接 kill
         不是我起的 ⇒ **如实说"没收掉"**，并指出该去哪儿收
```

`smoke-resident.ps1` 10 条判据盯着，其中三条是"它会不会骗人"：
**它真活过会话一了吗**（不是又起了一个像的：`pid` + `started_ms` 对得上）、
**会话二接上的是同一个进程吗**（`sessions_served` 在涨、内存没重读）、
**它真能被收掉吗**（走它自己声明的入口，不是中控杀它）。

> 这一块最值得记的不是代码，是那两个坑：**都藏在"看起来成功了"后面。**
> 一个是"读出来是空的但不报错"，一个是"判据的证据明明在 stderr 里、通配符没对上"。
> 前者要改实现，后者要改判据 —— **但都得先承认"绿字不是证据"**。

#### ✅ 2026-09-20：**MCP 桥**（`harness-mcp`）—— "宿主"那句话落地的样子

附录 §10 早就把关系定死了：**MCP server 是框架里的一个 kind**，
**框架是 MCP 的宿主，不是替代品**。这一版就是照着它写的那一行字：

```text
   智能体 ──(我们的协议)──▶ 桥（一个普通工具服务）──(MCP/JSON-RPC over stdio)──▶ MCP server
```

**它不新增任何一种东西**：对智能体它就是又一个工具服务，对中控它和其它服务完全同形
（自报 manifest、受绑定与能力约束、结果过契约闸门）。启动时做三件事：
拉起子进程 → `initialize` → **`tools/list` 问一次**，然后把**每个 MCP 工具
原样报成我们的工具** —— 于是名片、`help`、能力、绑定那一整套**一个字都不用改**。

**三个待定项在这条路上自己有了答案**（不需要额外发明）：

| 待定 | 答案 | 为什么是这个 |
|---|---|---|
| **#49 渐进披露** | **保留原生声明通道**，渐进披露由我们这层给 | 把 MCP 工具塞进一个通用调度器，会丢掉模型**被专门训练过**的 function calling 形态（§5.4.2 已经比过一次）。代价：工具多时名片会长 —— 那时再谈分组 |
| **#50 健康与重连** | **不自动重连**：对端没了 ⇒ 桥报 offline 退出，让中控那条**现成的** `service_down` 路接管 | 桥**不自己编答复** —— 自己答一条只会让同一件事有两个说法。敕令里带的还是**桥自己的遗嘱**。⚠️ 而"对端没了"这件事**2026-09-20 才变得可靠**：它起的孙子会攥着它的 stdout，光等 EOF 会**等满整个超时** —— 现在每一轮顺便 `try_wait()` 问进程本身 |
| **#54 白名单粒度** | **按工具，默认拒绝**（`--allow <工具名>`） | 白名单是**部署方**定的，而桥照着**别人的**工具表干活 —— 那个 server 明天多报一个工具，桥不该自动把它的权限提上去 |

三条最容易做错的映射，都有判据盯着：

* **工具失败 ≠ 调用失败**：MCP 的 `isError: true` 是**结果里的数据** ——
  调用确实发生了，所以 `effect` 照样 `confirmed`，而"它说自己失败了"一字不改地放在
  `data.is_error` 里（同终端那条：命令 exit 3 也还是 confirmed）；
* **认不出来的内容不许假装看见**：`content` 里不是文本的块（图片之类）留在 `data.mcp`，
  并在 `output` 里**留一行说清"这块我不认识"** —— 静默丢掉会让模型以为对端什么都没回；
* **超时是"我不知道结果"**：`effect: unverifiable` + `code: timeout`，
  而 `why` 里就写着"我不知道它做没做"（那句在 `why` 里，不在 `remedy` 里 —— 两样别混）。

对端是 `mock-mcp`（本仓库里的最小 MCP server，一百多行）——
它同时是**这份协议的可读样本**：想接自己的 MCP server 的人，看它比看规范快。

> 顺带补上上一轮标出来的缺口：**7 种消息现在真的都过了一遍套接字**
> （`harness-ipc/tests/conformance.rs`，两个方向各一次，用真的信封 + 真的编解码器）。
> 在那之前"承载全部 7 种"只是结构上成立，没人验过。

#### ✅ 2026-09-20：**提示词实例**（`prompts` / `prompt` 两个 op）

§3 的清单最后还差两类，这是其中一类。"提示词"在表里的定义是
**可被引用、可组合的文本片段，版本化，不需常驻** —— 落地形状：

```text
   --prompts <目录>        每份 .md 就是一段可引用的提示词
   prompts                看库里有什么（名字 / 版本 / 字节数，**不给正文**）
   prompt                 把点名的几段**注入**某个智能体的上下文
```

**为什么它落在中控**：片段的去处是**智能体的上下文**，而往上下文里塞东西的通道
只有 `inject` —— 方向规则一写着"**只有中控能发**"。所以"把哪一段念给谁听"
只能由中控做（§4.4）。

三条规矩，每条都有理由：

| 规矩 | 为什么 |
|---|---|
| **看和念分开**（`prompts` 只给元信息，`prompt` 才注入） | 合成一个的话，"看一眼有什么"就变成了一个能改上下文权限的动作 |
| **只有 `user` 能注入** | 它写的是**规矩** —— 和改授权同一类动作。让智能体或通道给自己灌指令，这套模型里最不能开的口子之一 |
| **注入是 append-only，前缀一个字不动** | 前缀是字节冻结的（§15.2）。注入顺手重编前缀的话，**缓存从那一刻起全废** —— 判据直接盯着 `prompt_compiled` 全程只有 1 条 |

另外两条细节：**抬头必须留**（`【提示词 名字@版本】`）—— 否则事后没人知道
"这句话是哪个片段说的、哪一版"；**坏文件不许悄悄跳过**（空的那段进 `skipped` 并报出来，
同技能服务那条纪律）。`prompts` 和 `prompt` **报的是同一份**（都重读目录）——
一个说 @1、另一个念 @2 的自相矛盾比"都不重读"更坏，因为它让人以为**看过了就等于念过了**。

### 阶段 4：与工具实例联动实测（我来驱动）

#### ✅ 2026-09-19：**智能体层补上了**（4a 的前半，路线图原来漏掉的那一环）

```text
crates/harness-agent/src/prompt.rs   提示词编译 + 组合清单
crates/harness-agent/src/model.rs    模型适配层 + 脚本化 mock
crates/harness-agent/src/script.rs   mock 脚本（NDJSON，一行一步）
crates/harness-agent/src/main.rs     回合循环：调模型 → 调工具 → 收结果 → 再调
scripts/smoke-agent.ps1              验收：两个场景、13 条判据
```

跑法：`pwsh -File scripts/smoke-agent.ps1`。

> **这是第一次真的闭上一个环**：
> ```text

>                      ▲                                    │
>                      └──────────── result ─────────────────┘
> ```
> 而且智能体会**把上一步的结果读进去再决定下一步** ——
> mock 脚本里写 `"instance_id": "$last.instance_id"`，它用的是 `open` 真正返回的那个 id，

**两个场景**：A 正常干完 + **中途工具崩了**（敕令真的发出来、未决调用被结掉）；
B 先调错工具 → 收到带出口的报错 → 改对继续。

**这一轮把两件一直悬着的事推进了：**

**一、敕令（`inject`）第一次真的被发出去。** 协议定义它、方向规则校验它，
但在此之前从来没有一行代码产生过一条 —— 因为没有"有上下文的智能体"可以注入。
现在工具下线时中控会往智能体注一条三段式敕令（事实 / 影响 / 出口）。

**二、`prompt_compiled` 事件第一次让不变量二可检。** 模型看到的那段系统提示
不是消息流里的任何一条，所以只能显式报给中控；第 8 条判据断言它**在会话日志里**。
顺带留了**组合清单**（§15.3）：这次生成用了哪个人设的哪个版本、哪些工具实例。

> **§15.2 那条硬约束落地了：拼装在绑定时刻凝固。**
> 提示词**编译一次就冻住**（第 10 条判据盯着编译的确定性），
> 工具集变了**不改提示词，而是追加一条敕令** —— 前缀不动，变化走 append-only。
> 这正是我们讨论了好几轮的那件事，现在它是代码。

#### ⚠️ 路线图原来漏了这一环，已经补上

"要测 agent 循环"里，但从来没作为一个交付物出现过。结果是三轮里建好了
"说话的通道 / 能用的手 / 记得住的脑"，唯独没有那个**主体**。

**记录在这里，避免以后再犯**：任何一个阶段，如果它的验收标准里出现了
"跑通 X → Y → Z 的环"，那**环上每一个节点都必须在清单里各占一行**。

#### ⚠️ 这一轮抓到的两个 bug，其实是同一个盲区

1. **`fault()` 只记账、不投递。** 它走的是 `record_and_print` —— 那是
   "记进日志 + 给控制台看"，**不写给收件人**。这个错误被掩盖了整整两个阶段，
   因为在此之前收件人一直是 console，而 **console 就是读 stdout 的那个** ——
   "打印"恰好等于"投递"。直到收件人变成一个真的实例（智能体），它才露出来：
   智能体苦等 30 秒超时。
2. **`fault()` 不带 `corr`。** 报错是关于"某一次调用"的，却不说是哪一次 ——
   收件人只能靠猜。报错必须能配对，否则它就不是给调用方的，只是给旁观者的。

> 教训一句话：**"记下来"和"送到了"是两件事，"说清了"和"说给谁"也是两件事。**
> 四个组合里，我们一路只做对了两个 —— 因为前两个阶段的收件人恰好是控制台。

以编辑器为例：**改文件 → 触发编译 → 看整条链路**。验证这四样：

| 验证什么 | 在哪 |
|---|---|
| **写互斥**（同时只有一个 agent 持有某路径写权） | §5.15 |
| **路径围栏**（允许向内 cd、禁止向外） | §7.1 |
| **敕令**（工具集变了，模型在不破坏缓存的前提下知道） | §4.4 |
| **重放不变量**（会话日志能重建模型看到的一切） | §9 |

**而且这里的"测"是用 stdio 真的跟它对话，不是跑断言** ——
这正好是 §5.4.1 那种做法：**用真实调用量出数字，再拿数字改设计。**
那次测出来的"加一个工具作废 89% 会话"就是这么来的。

#### 4a：mock 阶段 —— 测**系统**

**为什么先 mock**：它把"系统的 bug"和"模型的 bug"分开。
一上来接真实 API，出了问题你**分不清是协议错了、状态错了、还是模型不听话**。

**mock 的形态不是"返回一句话"，是脚本化**：给一个响应序列，按顺序吐。
因为要测 agent 循环，mock 必须能产生：

| 要能产生 | 用来测 |
|---|---|
| 普通文本 | 最基本的通路 |
| **工具调用**（单个 / 多个 / 流式分片） | 循环、配对、`corr_id` |
| **畸形输出** | 参数解不出来时的**报错即手册**（§5.5 那条的前半）—— ✅ 2026-09-20 做了，见下 |

**而且它必须能演坏的那部分** —— 这才是它作为测试工具的价值：

| 模拟什么 | 测什么 |
|---|---|
| 工具返回错误 | 错误码与补救说明（规范 §11.5） |
| **服务崩掉** | 敕令的触发与措辞（§4.6） |
| **输出超长** | 溢出与截断（§5.17） |
| **撞上下文上限** | 压缩的触发点（§5.4.3） |

> **这一半测的是"系统对不对"：协议、状态、顺序、故障处理。**
> 可复现 —— 同样的输入序列应当给同样的输出。

**这套路子你是熟的**：EasyTerminal 的 README 就写着
"未配置模型时 mock 走同一引擎，可完整验证闭环"，
而且你们修过一次它的坑（"MockBackend 只认最近一条 user 之后的 tool 结果"）。

#### 4b：真实 DeepSeek 阶段 —— 测**模型**

#### ✅ 2026-09-20：**畸形输出那条补上了** —— 报错即手册

4a 里一直挂着一件事：**模型吐了畸形输出会怎样**。做出来的答案分两半，
因为"畸形"其实是**两种完全不同的东西**：

| 形状 | 是什么 | 怎么处理 |
|---|---|---|
| **回包整体读不懂**（半截输出、根本不是 JSON）| **模型这条路断了** | `ModelReply::failed` —— **不许**当成模型的回答（那正是"把故障说成结论"）|
| **工具调用的参数解不出来** | **模型还想干活，只是参数写坏了** | **这一条根本不发出去**，回它一条**报错即手册** |

第二种才是真问题。在 2026-09-20 之前，`arguments` 解析失败会被编成一个
`{"_raw":…,"_parse_error":true}` **照样发给工具** —— 那有三个坏处：
**① 等于替模型编了它没说的话；② 工具会回一句"缺少参数"，指不到真正的原因；
③ 那一轮本来能救回来，却成了一次没人知道想干什么的调用。**

现在它回的是这样一条（真跑出来的原话）：

```text
**[参数不合法]** 你给 `open` 的参数不是合法 JSON：key must be a string at line 1 column 2。
- **这次调用没有发生**：工具那边根本不知道你调过它 —— 别以为它做了一半。
- **`open` 的参数长这样**：{"additionalProperties":false,"properties":{...},
  "required":["path"],"type":"object"}
- 拿不准就**先调它的 `help`**（渐进披露那条：别猜参数）—— 一轮只改一次……
- **别原样重发**：解不出来的那一版再发一次，结果还是这个。
```

三件事齐了才算"手册"而不是"抱怨"：**事实**（原话 + 哪儿不对）、
**影响**（这次调用没有发生）、**出口**（参数表）。
而那份参数表是**抄的**，不是这儿编的 —— 它就是从服务 manifest 编译来的名片。

顺带一条可观测性：`trace.bad_calls` 是**单独一个数**。为什么它不能混进
`tool_calls`：「模型不听话」和「我们的解析坏了」在调用侧长得一模一样，
分不开就永远查不出是哪一边。

这一半测 mock 根本测不到的：

| 测什么 | 在哪 |
|---|---|
| 模型能不能正确调用工具（工具定义清不清楚） | 规范 §11.1 |
| **敕令的措辞够不够懂**（那三段：事实 / 影响 / 出口） | §4.4 |
| **报错即手册**能不能把模型救回来 | §5.5 |
| **压缩之后它还记不记得任务** | §5.4.3 |

**这一半不可复现**，所以每次都要记日志 —— 而且它失败时，
你要能回头判断"这是模型的错还是系统的错"，这正是 4a 存在的意义。

**一、入口从常量变成了实例。** 原来 `console` 是个写死的常量（15 处引用，

```text

```

**二、会话成了一等对象。** 它不再只是"一个 sid + 一个目录"，
而是**坐标 + 装配单**：状态、托管、点名的智能体、现在有谁连着。
而且 **挂起 / 恢复 / 结束** 分得开了 —— §12.7 早就说"这两个要分开"
（"我先去干别的" vs "这事做完了"），现在有代码也有判据：

```text
suspend → 回收实例 + state=suspended（会话留着）
resume  → 照**同一批 id** 重新装配
end     → 回收 + 归档 + state=ended，之后 resume 会被拒
```

回收顺序是**先敕令、再工具、最后智能体** —— 敕令得趁智能体还活着把话说完；
而它死了也一样，那条敕令落在日志里，下次恢复时读得到。

> **顺带被自己的验收脚本咬了一口**：我在进程还在跑的时候去读日志，
> 读不到刚发生的事 —— 因为**日志是带缓冲的，只在落盘屏障上刷**。
> 这不是 bug 而是设计：**直播流是即时刷的（每次 write_line 都 flush），
> 日志是批的**。想立刻知道发生了什么就看流，想可重放就看日志。
> 判据因此改成"等进程退出（那会走一次屏障）再读日志"。

#### ✅ 2026-09-19：**跨进程恢复** —— 不变量二第一次真的被用上

```text
scripts/smoke-resume.ps1   验收：7 条判据（两轮：跑一轮 → 停掉 → 冷启动）
```

跑法：`pwsh -File scripts/smoke-resume.ps1`。

**先说这一轮审计出来的坏消息：不变量二一直是假的。**
智能体往上下文里放了**六种**东西（用户 / 助手文本 / 工具调用 / 工具结果 / 敕令 / 摘要），
而日志里只有**一种**（系统提示）。也就是说：**日志根本重建不出模型看到的东西** ——
而"可重放"那条不变量从一开始就写着"抵达模型请求的一切都必须能从日志重建"。

修法是新增两类记录：

| 记录 | 谁报 | 报什么 |
|---|---|---|
| `model_item` | 智能体 | 它往上下文里放的**每一样东西**（含渲染之后的那份文本）|
| `compaction` | 智能体 | 切点 / 插入点 / 摘要 —— 重放要靠它**把同一刀切回去** |

**为什么不"从协议消息推"**：**渲染是有损耗的**。工具结果在日志里是 `result`
报文的原样，而模型看到的是加工过的那份（挑 `output`、追加【错误码】【下一步】）。
**只有智能体自己知道它到底喂了什么** —— 所以只能由它报。

恢复的实测输出：

```text
[ctrl] 恢复会话 s-resume：托管 1 条，点名 None，日志到 seq 23
[agent] 恢复上下文：8 项，系统提示一致，日志到 seq 23
```

**恢复得回来什么、回不来什么，这次说清了**：

| | 回得来吗 | 为什么 |
|---|---|---|
| 会话坐标（状态 / 托管 / 点名的智能体）| ✅ | 在 `meta.json` 里 |
| 模型看到的上下文 | ✅ | 在**日志**里，走 `replay` |
| **工具实例**（`t-1`…）| ❌ | **进程内的东西，跟着服务一起死了** |

最后一行**不是缺陷，是定义** —— §12.7 那句"挂起 = 工具实例收掉、会话留着"
本来就是这个意思。

另外智能体**不自己去读日志**：日志格式归中控，它只提一个语义请求
（`{"op":"replay"}` = "给我我上次看到过的东西"）。

#### ⚠️ 同一个坑的**第三处**

第一次跑就卡住，根因还是它：**`reply()` 用的是 `record_and_print`**。
前两处是 `fault()` 和"结掉未决调用"，这一处是**中控的回复本身**。

三次都是同一个形状 —— `record_and_print` 只是"记进日志 + 给控制台看"，
**它不投递**；而收件人一直是 console（就是读 stdout 的那个）的时候，
"打印"恰好等于"投递"，这个错就一直藏着。

**所以这次不是"记住别用它"，是把它删掉**：中控现在**只有一条出口**（`route`）。
结构性修复比纪律可靠 —— 这条也写进决策册了。

**不给就是空表 ⇒ 默认拒绝。**

现在的拒绝长这样：

```text

remedy: 你被授权的是：term:1。要更多，得让中控给你签发（§2.3）；
        别去猜别的实例名 —— 那不是你能决定的
```

#### ⚠️ 这一轮的两个 bug，都是我自己引入又自己抓到的

**一、启动握手把消息吞了。** 为了拿授权，智能体在主循环开始前要做一次往返；
而那几百毫秒里控制台的任务就到了 —— 那个"只等自己那条回信"的循环**把它丢了**。
修法：握手期间收到的非目标消息进 inbox，主循环先排空它。

**二、同一个 bug 有两份拷贝。** 为了跨进程恢复，我另外写过一个专用的等待循环，
**它没有 inbox** —— 于是恢复那一轮又把任务丢了。修法是删掉它，
两条路都走同一个 `ask_ctrl`。

> **少一份实现，就少一处漏。** 这和那三次"记账 ≠ 投递"是同一个教训的两面。

#### ✅ 2026-09-19：**重新托管** —— 项目搬走这件事，终于执行得了

```text
scripts/smoke-rehost.ps1   验收：8 条判据
```

跑法：`pwsh -File scripts/smoke-rehost.ps1`。

这条验收的是那句"**记忆跟着会话走，项目搬走就在会话里委托新的路径**"。
它以前**执行不了任何东西**：`host` 只是记账，服务的围栏是服务表里写死的参数 ——
中控甚至不知道那串 `--fence ...` 是什么，对它来说就是普通参数，照抄转发而已。

现在三件事连上了：

| 环节 | 从哪来 |
|---|---|
| **围栏** | 服务表只声明"我需要一条围栏"（`wants_fence`），**具体是哪条由中控在装配时从会话取** |
| **时机** | `--host <路径>` 让会话**开会时就带**托管路径（不然要围栏的服务永远起不来）|
| **生效** | `host` / `unhost` **立即生效** —— 中控把那些服务收掉、照新路径重新装配 |

实测的 stderr（这就是那条完整的搬家链）：

```text
[ctrl] 开会话时就托管：\\?\...\projA
[ctrl] 拉起 term:1（... --fence \\?\...\projA）      ← 围栏来自会话，不是服务表
[ctrl] 拉起 term:2（... --fence ...\projC）          ← 这个写死在表里
[ctrl] 重新托管：收掉 term:1（连带 0 个实例）
[ctrl] 会话现在没有托管路径 —— 需要围栏的服务先不起，等 host
[ctrl] 拉起 term:1（... --fence \\?\...\projB）      ← 新的路径，新的围栏
```

**搬家的顺序是有讲究的：先 `unhost` 旧的，再 `host` 新的。** 因为**服务的围栏根必须存在**
（不存在它就不让干活），而真搬家之后旧目录早就不在了。中间那一瞬会话是空的 ——
那时要围栏的服务先不起，**那不是失败，是"没到时候"**。

顺带补上了授权缺的那一半：**光有实例名白名单不够** ——
一个绑在别的路径上的终端实例，本会话的智能体照样能签进去，而它眼里压根不是这个项目。
所以现在还要判：**目标实例的围栏必须落在本会话托管的范围里**。

#### ⚠️ 第一次跑"重新托管"就撞上一个真 bug

```text
[ctrl] 拉起 term:1（... --fence projB）
[ctrl] term:1 自报 state="online"        ← 新的刚起来
[ctrl] term:1 自报 state="offline"       ← 旧进程临死前吐的这一条，把它收了
[ctrl] 服务 term:1 退出了
```

**重新装配会把同一个 id 再拉起来，而旧进程的迟到消息还会到** ——
ctrl 分不清"哪一代"，于是新实例被旧消息打死。

修法不需要改协议：**中控一直知道每行是哪根管道来的**。给每次拉起编个号，
读线程把它带上，对不上代的直接丢：

```text
[ctrl] 丢掉一条来自旧世代（term:1 gen1）的消息
```

> 这类"**同一个 id、新的化身**"的问题，任何会重新装配的系统都会遇到。
> 它和"记账 ≠ 投递"一样，是**分布式本身的税** —— 早遇到比晚遇到好。

**在这之前，§2.3 那条"绑定"只是一张图纸。** 它实际是服务表里的一行静态配置 ——
于是"名册只追加 + 回合边界扫一遍 + 发一条敕令"整套机制
**永远等不到变化**。链接好了，就是没人按开关。现在按下它，整条链自己走完：

```text

                              │
                              ▼
        智能体下一回合开始前扫一遍 ─▶ 换名册（function 定义数组）
                              │
        系统提示**一个字都不动**（§15.2：拼装冻结，变化走 append-only）
```

**验收的方式是让同一个调用演三次**：mock 脚本里三幕都调 `echo:1` ——
第一次**被授权挡下**、第二次**成了**、第三次**又被挡下**，
差别只在授权。这比"断言中控改了内存里的表"有力得多：

> 它证的是**授权真的改变了行为**，不是"我改了个数据结构"。

**四条判据值得单独说**（它们各自钉住一个不变量）：

| 判据 | 钉住什么 |
|---|---|
| 敕令进了 **`model_item`/`injected`** | "发出去"不等于"进了模型上下文"——**只有后者算数** |
| `prompt_compiled` 始终只有 **1 条** | §15.2：前缀冻结。工具集变了**不改提示词** |
| 换名册也进日志（`toolset_changed`） | 不变量二：名册是**模型可见的东西**，可见即已记录 |
| 一条 **`agent` 上限的通道 grant 被拒** | 授权只发给智能体？**不** —— 是**只有用户能改授权** |
| 同一条 `term status`：控制台放行、被降级的通道也放行，**但那个通道的 `run` 被拒** | **凭证的默认值是"拒绝"** —— 见下面的坑 |

最后一条不是洁癖：让智能体（或某个工具）给自己加权限，
"默认拒绝的绑定"（§5.10）立刻就成了一句空话。

**同一轮里还抓到一个真洞，值得单独记**：中控原来**只给智能体的请求**附凭证，
而服务的判断是"**没有这个字段 = 调用方不是智能体 = 全权**"。
于是 —— **一条被降级的通道能全权指挥工具**：`--channel 微信:agent` 转来的消息
权威降到 `agent`（按 §4.5 只能"提意见"），可它请求里没有 `granted` 字段，
`proc.exec` 照样给。**权威分级只改了信封上的一个字，没改它能不能用工具。**

现在中控给**每个发给工具服务的请求**盖章（`caller_kind` + `granted`），
服务那边**没章就是默认拒绝**（只放行 `help` / `status` / `ping` 这种零能力的诊断动作 ——
出问题时得有人能问话）。**两个默认值终于统一成"拒绝"了。**

**代价说清楚**：名册（`tools` 数组）在缓存前缀里，换了它，**它之后的那截全作废**。
所以刷新只发生在**回合边界**、而且**只动名册** —— 系统提示一个字不重写。
这就是你当时那个判断的落地：**"反正都是炸缓存，不如把新东西放少点。"**

```text
crates/harness-core/src/id.rs          short_rand：8 位十六进制（不引依赖；2026-09-20 从 4 位加长）
```

四层都有 id（会话 `s-…`、智能体 `agent:dada`、工具服务 `term:1`、

| 原来 | 后果 | 现在 |
|---|---|---|
| 注册表 `insert` 静默覆盖 | 两个进程都用 `term:1` ⇒ 后来者顶掉先来者，**发给它的请求转手交给新进程** | 撞 id 一律拒，并说清是谁占着它 |

> `term:1` 谁都猜得到，而猜到它一点用都没有（授权靠签发、归属靠 owner、能力靠比对）。
> **安全不建立在"猜不到 id"上。**

#### ✅ 2026-09-19：**磁盘指纹** —— 别把别人的改动静默抹掉


**写锁的用途要说准**：它保护的是"**别的 AI 别大批量覆盖**"，不是"用户别碰" ——
用户随时会在自己的 IDE / 命令行里改同一个文件，**那不是异常，是常态。**
（§5.15 原来只说了"写锁挡不住用户的 IDE 和命令行"，但没说挡不住之后该怎么办。）

所以策略是**跟着磁盘走**，而不是把门锁死（第一版我写成"变了就拒"——**那是错的**，
代价还不只是别扭：AI 得 close 再 open，**丢掉整条回滚历史**）。现在三条：

| 情形 | 怎么办 |
|---|---|
| 发现磁盘变了 | 把磁盘那份**读进来当作一条 `external` revision**（历史连贯、账上有它）|
| `edit` | 照常替换 —— 安全性来自**内容**（`old` 唯一命中），**不来自时间戳**：用户改别处 ⇒ **两边并存**；改的正是那一处 ⇒ `old` 命不中（常规拒绝 + 一句"外界刚改过"）|
| `revert` | 它是**故意整份覆盖**，没有内容判据可依 ⇒ 守"**不许跨过用户的改动**"（判据是历史里那条 `external`，精确判定）|

于是"静默丢数据"被两条机制堵上：**能判内容的地方判内容，判不了的地方判历史。**
顺带纠了规范里一处方向错误：原来写的是"**可选的** `expect_hash` —— 调用方给了才比对"，
而**核对是服务自己的义务**。

#### ✅ 2026-09-20：**`lifecycle` 真的会执行了** —— 最后一个"声明了没人执行"的字段

```text
规范-工具服务 §11.10            per_call / per_session 的含义与两条规则
```

它的落地含义是**拉起时机**：`per_session`（默认）= 会话装配时就拉；`per_call` = **装配时不拉，
第一次有请求指向它才拉**（那条请求走"没报到先攒着"那条路等它上来 —— 两条机制天生一对）；
`resident`（跨会话常驻）**没实现，闸门会拦**。

> **它不负责"用完就收"** —— §5.20 定过不做自动回收。它解决的是很实在的一句：
> **原来"开会话"等于"把表里每个服务都拖起来"**，哪怕这次会话根本用不到它们。

**一条设计上的鸡生蛋**：要看 manifest 才知道它想怎么被起，可**要看 manifest 就得先把它起来**。
所以决定权在**服务表**（部署配置），manifest 是**服务自述** —— 分工和 `wants_fence` 一模一样。
两者可以不同（运营者可以让一个 `per_call` 的服务开会话就起），`list` 上并排显示
`lifecycle` / `lifecycle_declared` / `lifecycle_mismatch`：**不一致不是错，但不许藏起来。**

**而且新规则第一次生效就抓到了我自己**：`ToolDecl::new` 的默认值写的是 `per_call`，
而几个工具显式写了 `per_session` ⇒ **服务自己内部就不一致** ⇒ `smoke-term` 的 16 条判据当场全红。
**默认值必须和部署默认一致** —— 这是那个坑的根。

```text
crates/harness-ctrl/src/main.rs   分派前落盘（判据 = 服务的 destructiveHint）+ 未报到先攒着
scripts/smoke-editor.ps1          验收：第 17/18 条（edit 落了、read 没落）
```

这两件都是**审计照着代码查出来的**（不是计划里的），而且第二件是审计顺手照出来的洞：

1. **落盘屏障的第二个边界**（§5.5 说三个，原来只做了一个）。有副作用的工具 **分派之前先落一次盘** ——
   它防的是**"日志说没做、文件其实改了"**：请求还在写缓冲里，服务已经把文件改了，这时崩了就没法追溯。
   判据是**服务自己声明的 `destructiveHint`**（中控不必懂工具语义），读不到就**保守落一次**并出声。
   `--debug-barriers` 让这条机制可验（正常路径不出声，不然终端每跑一条命令就一行）。
2. **请求不许抢在服务自报家门之前投出去**。原来 `route` 会把请求递给一个**还没报到**的服务 ——
   于是**契约闸门还没看过它的 manifest，请求就已经到它手上了**，那道关等于没有
   （顺带 `destructiveHint` 读不到，"要不要先落盘"也判不出来）。现在：没报到就**按到达顺序攒着**，
   报到后照序放行；超宽限（`--startup-grace-ms`，默认 2s）逐个拒掉。

**两条实现纪律都是踩出来的**：① 队列里放**要投的那一行**、不放信封 —— 放信封、放行时重跑路由，
会让**同一条请求记两遍日志**（`smoke-stdio` 的"console 输入 9 条"当场变成 13 条）；
② **"要不要先落盘"必须在投递那一刻算** —— 排队时算必然是"读不到声明"，于是连 `read` 都保守落盘。

#### ✅ 2026-09-20：**背压** —— 输出比消费快得多的时候谁去扛

```text
crates/harness-term/src/term.rs    输出缓冲：内存留尾巴 + 按字符边界溢到磁盘
crates/harness-term/src/main.rs    --inline-limit / --memory-cap；run 只看头尾，read 是分页器
scripts/smoke-spill.ps1            验收：9 条判据（关键一条是"分页拼回来 == 原文"）
```

跑法：`pwsh -File scripts/smoke-spill.ps1`。

这条在文档里挂了两轮，卡点是**两个数**和一个**死循环**，一次全解掉：

| 数 | 值 | 为什么 |
|---|---|---|
| 一次结果里最多内联多少 | **50 000 B**（`--inline-limit`）| §5.4 那批数据里 dsh 的 `maxInlineBytes`；**单位是字节** —— 算不准别家的分词器 |
| 内存缓冲留多少 | **1 MiB**（`--memory-cap`）| 够装下正常命令，扛不住 `yes` |

两个数都是**部署选择**，不是普适值（dsh 把默认写成"省略 = 完全禁用"，态度很清楚）。

**两条不同的路，别混**：**背压**是"缓冲满了往磁盘溢"（内存只留尾巴，前面的按**字符边界**
挪到 `data/spill/<sid>/<实例>.log`）；**内联上限**是"一次结果里塞多少"（头尾 50/50 +
一句省略说明，通知的字节先从预算里扣）。

而**死循环**（"读全文还得再跑一条命令"）的解是**游标**：全文留在实例里（内存 + 溢出文件），
`read` 跨两段按**全局字节偏移**读 —— **想全看是多读几页**。所以 `read` 是**分页器**
（默认一页 = 内联上限，`next_cursor` 指路），头尾摘要只用于 `run` 的结果。

> **落地当天抓到真 bug**：溢出让内存变短，而 `running.to` 记的变成了**内存长度** ⇒
> `run` 只回"溢出后剩下那点字节"，前面整段静默丢掉（它还在文件里，只是没人去取）。
> 教训：**全局偏移这个口径，每一处用到它的地方都得说清是全局还是局部。**

```text
why:     调 `run` 需要的能力你没有：proc.exec
granted: （什么都没有）
remedy:  能力是中控签发的（§2.3）：要么让它给你加上这几条，
         要么换个不需要这些能力的做法。别重试 —— 你不是偶尔被挡，是本来就没这个资格
```

而手册是**分章**的（一次全倒会吃掉上下文）：

```text
overview  —  概览
two-modes —  命令模式与会话模式（第一版只有前者）
cursor    —  输出与游标
errors    —  错误码与补救
```

> 这三件也顺手回答了"**这个分布式架构到底在解决什么**"：
> 中控存在的意义不是"转发得比直连快"，而是**它掌握着别处没有的东西**
> （会话托管了什么、谁被授权用什么、哪个实例是第几代），
> 然后把**其余的一切**——手册怎么写、能力怎么比、结果怎么描述——**留在做那件事的人手里**。

#### 六、同一轮里顺手补的两处（都是"文档说做了、其实是空的"那一类）

**一、不变量一原来是个空壳 —— 比不写更糟。**

```rust
pub fn assert_transport_agnostic() -> Result<(), String> {
    Ok(())   // ← 这就叫"写进代码"了？
}
```

文档里那句"三条不变量**写进代码，不是文档里的一句希望**"，
其中一条就真的只是一句希望。而且**空壳断言比不写更糟**：它让读代码的人以为这里守住了一道。

它现在是一条**构建期断言** —— 查 `harness-core` 自己的依赖表，只许有 `serde` / `serde_json`：

```text
谁往 core 里塞 tokio / reqwest / 管道，这条测试就红
```

**为什么不能运行时断言**：不变量一的本质是**结构性的**（协议层不许认识任何传输）。
结构性的东西，运行时再怎么断言都只是自说自话；而"core 依赖了什么"是**可查的事实**。

**二、`cancel` 走通了。** 它定义了、方向规则也校验了，但**从来没被产生过** ——
超时只是"调用方不等了"，工具那边**还在跑**。现在：

```text
[agent] 超时：给 1 个调用发了 cancel
[term]  收到 cancel（corr=…）：确实停下了
                                        → 回 partial + canceled：
                                          "你取消了它 —— 我确实停了，所以它做了一半（不是没做）"
```

这就是 §2.3 那句"**与其要求工具保证能停，不如要求它诚实报告停没停**"落到代码的样子。
验收 `pwsh -File scripts/smoke-cancel.ps1`（7 条判据）。

**三、顺手抓到一个"内容被丢掉"的 bug。** 那个 `canceled` 的答复里既有输出、又有"为什么"——
而 `render_result` 只挑 `output`，**把 `why` 扔了**。于是模型看到的是
"一段输出 + [错误码] canceled"，**不知道是被谁取消的、停在哪一步**。
现在它会带上一行 `[为什么]`。

> 这类"有 output 也有 why"的结果**只在失败一半时出现**（`partial`）——
> 也就是说：**恰好是最需要解释的那种情况，解释被丢了。**

#### 七、2026-09-20 审计：两个真 bug、一个同族第四次、一处工程风险

这一轮不是"再写点功能"，是**对着代码逐条问"你说你做到了，证据呢"**。
方法：`cargo test` 看 **exit code**（不是看空输出）、26 个验收脚本全跑、
然后**把日志逐条摊开对**（不是只看脚本打的绿字）。

| 抓到什么 | 本质 | 怎么处理 |
|---|---|---|
| **探针回包 100% 被判成孤儿结果**（`smoke-lifecycle` 实测 18 发 18 中）| **一张表被两处读，顺序没说清**：`on_service_line` 先 `pending.remove(corr)`、再 `route`；而方向规则四判"这结果是不是中控要过的"**查的正是 `pending`** —— 摘完了才问，当然说没有。后果是探针答复被丢（`route` 遇违规直接 `return`）+ 每轮一条假故障 | **三处写法统一成"先看、走完 `route` 再摘"**（`on_service_line` / `on_service_exited` / 报到超时）。判据：`smoke-lifecycle` 第 14/15 条，**对老代码会红** |
| **终端 `run` 每次都违反自己声明的形状** | 成功分支写 `"why": null`，而 `why` 声明的是 `string`、schema 闭合 —— 于是**每一条没被裁剪的普通命令**都挂着 `schema_violation`。它不是"闸门太严"：`why` 本来就不在 `required` 里，**什么都不想说时正确形状是"没有这个键"** | 改成"没话说就省键"。判据：`smoke-term` 第 19 条，**对老代码会红** |
| **"有副作用工具分派前先落盘"这条判据写错了对象** | 它只看"是不是 request"，于是**给智能体派活**也撞进来（智能体也是被拉起来的服务进程，`service.is_some()` 对它同样为真）⇒ 白 fsync + 印一句误导人的"读不到它的声明" | 判据加上 `!is_agent`，**跟注册关用同一个谓词**。这条**第一次就写错了**，是 `smoke-barrier` 第 9 条当场抓住的 |
| **三个屏障边界缺一个**，而且**连路都没有** | "我下一步要去问模型了"只有智能体知道，可日志**中控独占** —— 缺的不是一行调用，是一个 **op** | 中控开 `barrier` op，智能体每次 `model.reply()` 前喊一声。规范 §5.6；`smoke-barrier.ps1`（9 条判据） |
| **14.5k 行代码没有版本控制** | `git rev-parse --show-toplevel` 从项目里往上返回的是 **`D:/`** —— `.git` 在**盘根**、`master` 上一个 commit 都没有 | 给项目建**自己的**仓库 + `.gitignore`（`target/`、`data/`）+ 一条基线提交，之后的修改才有回退点 |
| **"凭什么能用"没说全**（审计顺手补的） | 授权的粒度是**实例**、能干的动作粒度是**能力** —— `grant` 敕令只说"你能用 `term:1` 了"，在只签了 `proc.read` 时**是真的、但会误导**。另外**只有凭证变了**会被名册指纹当成"什么都没发生" | 敕令里列出能力名（通配/空表各有说法）+ 前缀加一句**静态**期待"有工具 ≠ 有全部动作的资格"；两份指纹分开比 —— **只有凭证变时名册一个字都不动**（省一次缓存作废）。验收：`smoke-regrant` 第 19/20 条 |
| **能力拒绝的结果本身不合形**（写记忆服务时撞出来的） | `refuse_payload` 带一个 `caller_kind`（"我认为你是谁"），而**没有任何工具的 `output_schema` 声明过它** —— schema 是闭合的，于是**每一次能力拒绝都在违反它自己声明的形状**，投递闸门每次都得贴一张 `schema_violation`。它**一直躺在 `smoke-help-grant` 的日志里**，只是没有哪条判据去看那个字段 | 把 `caller_kind` 补进**协议基表**（它和 `granted` 是一对：一个说"你手里有什么"，一个说"我认为你是谁"—— 拒的时候两种补救不一样）。验收：`smoke-help-grant` 第 10 条、`smoke-mem` 第 19 条 |

> **这一轮最值得记的不是那两个 bug，是"新写一个服务会撞出旧账"。**
> `caller_kind` 这条从编辑器落地那天起就在，一个礼拜没人看见 ——
> 因为它**只在拒绝时出现**，而拒绝是"预期内的路径"，没人去查它合不合形。
> 写第三个服务时它自己冒出来了：**换一个实现者，等于换一双眼睛查同一套契约。**

**同一轮里还有两处"数"错了，都是没人查的那一类**：

* README 模块地图那行写"已定 **256**"，真值是 **257** —— 小节的数有
  `check-decisions.ps1` 盯着，**汇总的数没人盯**。这轮改成 261（又是四条新的），
  并在那一行明写"这一行脚本管不到"。
* 两条代码注释（`session_log.rs` 说"分派前那一次还没补"、`harness-ctrl` 的
  `ConsoleEof` 分支说"另外两个边界还没拍板"）**在代码改完之后就过期了**。
  这类注释是最脏的债 —— **没人跑得出来**。

> **这一轮真正的方法论只有一条**：绿字不能当证据。
> 两个 bug 都藏在"全绿"的验收脚本后面 —— 判据查的是"该发生的事发生了没有"，
> 而它们坏在"不该发生的事发生了没有"。
> 所以新判据一律**先拿老代码验一遍"它会不会红"**，红不了就说明这条判据在空转。



## 怎么用这份文档

拆成模块是为了**按模块讨论**，不是按模块实现。几点约定：

- **结论一律记进 [09-决策](10-决策.md)**，不要只留在对话里。
  「已定」划掉，「待定」新增。

- `规范-工具服务.md` 是**规范性**的，其余模块是探索性的。
