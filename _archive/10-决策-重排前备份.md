  `inspect(doc_id)` 返回的是这个具体文档的真实结构，而不是写死的 docstring ——
  **永远不会过期**（§5.11）。

  **点击不是运行。** 这是 §14.18"观察不可信"在 UI 层的对应物。（§12.5）
- ~~**引用要不要验证**~~ → **要**。不存在的渲染成普通文本（或灰掉），
  **不做成点了没反应的链接**，那既误导用户又掩盖幻觉。相对路径按工作区根解析。（§12.5）
- ~~**引用从哪来**~~ → **模型结构化输出**，不从自由文本里正则猜（容易误伤）；
  系统只渲染验证通过的那些。（§12.5）
- ~~**输入源变多怎么办**~~ → **统一成「带级别的消息」**：
  每条进入模型上下文的消息都带**来源 + 权威级别 + 信任级别**。
  **中控不只仲裁输出，也是输入的关卡**（双向）。（§4.5）
- ~~**谁能下指令**~~ → 一套规则：**用户能下指令；另一个 agent 只能提意见
  （哪怕它说得很确定）；窗口事件只是事实。** 三者不能混。（§4.5）
- ~~**接论坛的额外要求**~~ → **认识论标注**（`experience` / `opinion` / `world`）——
  别的 agent 说的是"会验的经验"还是"它的判断"，不是语气问题，是可靠性问题。（§4.5）
- ~~**会话与记忆的关系**~~ → **会话是写入单位，锚点是存放单位**。

### 第十六轮补充（2026-09-17）：授权收敛、锁与 GUI 边界

#### 已定

- ~~**用户需要托管什么**~~ → **只托管两样**：**一个窗口**（观察源）
  + **一组路径**（写入范围）。其他全是 GUI 的活计。（§7.1）
- ~~**窗口和路径的关系**~~ → **窗口给语境，路径给权限**，两者**可以不一致**
  （IDE 只开项目 A，但可以授权改共享库 B）。所以**显式托管比从窗口推更有表达力**；
  §14.7 那条"从 IDE 读"改为只用来推**语境和工作集**，不推授权。（§7.1）
- ~~**授权和互斥是不是一回事**~~ → **不是**。授权 = 用户决定"可以写哪些"；
  互斥 = 运行时保证"同一时刻只有一个在写"。
  **失败方式不同：授权缺失是"不许"，互斥冲突是"排队"。**（§7.1）
- ~~**终端谁管**~~ → **智能体自己统筹，中控不分配，只负责可见 + 兜底**：
  列表 / 屏幕 / 状态 / **闲置时长** / 归属 / 可手动杀 / **超时回收**。（§5.15）
- ~~**为什么要显示在中控台**~~ → 因为"一个东西一直挂在那"是真故障，
  而**智能体会忘了自己开过什么**（尤其压缩之后）。
  **别让用户手工收尸 —— 那是设计失败的标志。**（§5.15）
- ~~**编辑器化最大的好处**~~ → **写互斥**。
  **实例是天然的锁点** —— 无状态函数没地方挂锁，
  两个 agent 可以同时对同一文件 apply 互相覆盖。（§5.15）
- ~~**锁的规则**~~ → **读自由、写互斥**：同一时刻只有一个 agent 持有某路径写权；
  锁带持有者；**失效要能自己释放**；拿不到时排队还是报错要定。（§5.15）
- ~~**由此得到的原则**~~ → **要给它上锁，先给它一个实例。**
  凡是想序列化的资源，做成实例就自动有了挂锁的地方。（§5.15）
- ~~**桌宠属于框架吗**~~ → **不属于。** 它只是一个**订阅消息流的实例**，
  和聊天窗口、终端面板没有本质区别。**框架只提供"能订阅"，不提供"订阅者"。**（§12.6）
- ~~**所以 §9 那句话要升级**~~ → GUI 不只是消息流的投影，
  **还是可替换的外部客户端**。用户自己写桌宠是完全正常的用法。（§12.6）

### 第十七轮补充（2026-09-17）：读取旁路不做

#### 已定

- ~~**轻量读取要不要绕过编辑器实例（#90）**~~ → **不绕过，一切走实例。**
  理由：**一条路比两条路好维护**；旁路一旦存在，
  "写互斥"就得重新证明（会不会绕过锁？会不会读到半个状态？）。（§5.15）
- ~~**「读自由」这条规则的适用范围**~~ → 澄清：
  **直接读文件自由**（不经过实例）；**通过实例读不自由**（会占写权）。
  上面那条"读自由"说的是前者。（§5.15）
- ~~**这样做的代价**~~ → **持有者卡住会阻塞想读的人**。
  所以"失效要能自己释放"从好习惯升级为**关键路径**。（§5.15）
- ~~**以后真要优化时走哪条路**~~ → **走消息，不开旁路。**
  方向是**让想看的向持有的发信** —— actor 模型：
  **状态私有、交互只靠消息**，所有权模型统一，而且顺带解决"半个状态"。
  **依赖智能体间通信，现在不做。**（§5.15）
